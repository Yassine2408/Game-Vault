# GameVault — Your Gaming Journal & Backlog Tracker

A real-time game tracking web app for players who play a lot of games:
mark games as **finished** (with the exact date), track what you're **playing
right now**, log play sessions, rate games, and watch live Steam player
counts & community activity stream straight into your dashboard.

![stack](https://img.shields.io/badge/Next.js%2016-App%20Router-black) ![db](https://img.shields.io/badge/PostgreSQL-NeonDB--ready-00e599) ![realtime](https://img.shields.io/badge/realtime-socket.io-f43f5e)

## Features

- **Accounts** — register / login / logout with a beautiful animated auth
  screen. bcrypt-hashed passwords, JWT sessions in httpOnly cookies.
  One-click **demo vault** (`gamer@gamevault.app` / `demo1234`, pre-loaded
  with 35 games, 170 sessions).
- **Vault & statuses** — PLAYING, COMPLETED, ON_HOLD, BACKLOG, WISHLIST,
  DROPPED per user per game, with start date, finish date, rating (0-10),
  favorite, notes and hours.
- **Play sessions** — log minutes per day; totals and monthly charts update
  automatically.
- **Live catalog** — search the real Steam store and import any game
  (cover art, description, Metacritic, genres, platforms) without any API key.
- **Real-time everything (socket.io)** —
  - live Steam **concurrent player counts** for your tracked games (60 s poll)
  - **trending chart** (Steam most-played, 5 min poll)
  - **activity stream** — your actions broadcast instantly; other tabs sync
    without a refresh
  - **live stat counters** pushed on every mutation
- **Stats** — finishes/hours per month, top genres, rating distribution,
  completion rate.

## Database — local Postgres & NeonDB

The app speaks plain **PostgreSQL** through Prisma, so the same code runs
against a local server or against [Neon](https://neon.tech) — you only swap
`DATABASE_URL`.

### Local development

`scripts/pg-ensure.mjs` runs a **real PostgreSQL 18.6** server (binaries
shipped via npm, data stored in `db/pgdata`). It is invoked automatically by
`bun run dev` and `bun run db:push`, so a fresh copy boots its own database on Linux x64. On Windows, use a
Linux x64 WSL distribution and run the commands in its terminal. You can
also provide an existing PostgreSQL server via `DATABASE_URL`.

```bash
bun install
bun run db:generate
bun run db:push     # starts local Postgres if needed, pushes schema
bun run db:seed     # optional: demo user + catalog from the SQLite snapshot
bun run dev         # http://localhost:3000
```

### PostgreSQL for production

1. Create a project at <https://neon.tech> (Postgres 18) — copy both
   connection strings from the dashboard.
2. Fill `.env`:

   ```env
   # pooled endpoint — used by the app at runtime (serverless-friendly)
   DATABASE_URL="postgresql://USER:PASSWORD@EP-NAME-pooler.REGION.aws.neon.tech/neondb?sslmode=require"
   # direct endpoint — used by Prisma for migrations / db push
   DIRECT_URL="postgresql://USER:PASSWORD@EP-NAME.REGION.aws.neon.tech/neondb?sslmode=require"
   AUTH_SECRET="<paste a random value generated by openssl rand -hex 32>"
   ```

   `DIRECT_URL` is already declared in `prisma/schema.prisma`, following
   Neon's official Prisma guide (pooled driver + direct migrations).
3. Push the schema and start:

   ```bash
   bun run db:push
   ```

That's it — the schema (User, Game, Genre, Platform, LibraryEntry,
PlaySession) is created in Neon and the app connects over TLS.

### Vercel deployment

Import the GitHub repository as a Next.js project and set `DATABASE_URL`,
`DIRECT_URL`, and `AUTH_SECRET` in the Vercel environment. Run
`bun run db:push` against your production database once before testing sign-in.
If you seed the demo account, use a separate test database because its
credentials are public.

The default deployment runs the Next.js app. The Socket.IO service requires
its own deployment and routing as described below.

## Project layout

```
prisma/schema.prisma          # PostgreSQL schema (multi-user)
scripts/pg-ensure.mjs         # embedded local Postgres manager
scripts/seed-postgres.mjs     # data migration / demo seed
src/lib/auth.ts               # JWT session + bcrypt helpers
src/lib/db.ts                 # Prisma client (URL resolver for Neon/local)
src/lib/socket.tsx            # realtime client (zustand + react-query hooks)
src/app/api/auth/*            # register / login / logout / me
src/app/api/*                 # library, sessions, stats, facets, games, steam
mini-services/realtime-service/  # socket.io hub + Steam live polling (port 3003)
```

## Realtime service

The socket.io hub runs as an independent mini-service on port **3003**:

- exposes `/__notify` so Next.js API routes broadcast instantly after
  mutations (fire-and-forget, never blocks responses)
- polls Steam `GetNumberOfCurrentPlayers` for tracked games and
  `GetMostPlayedGames` for the trending chart
- generates the community pulse (online gamers, activity events)

The core app works with just Next.js and PostgreSQL. To enable realtime,
run `bun install` and `bun run dev` in `mini-services/realtime-service`
and route the Socket.IO endpoint to port 3003 using the supplied Caddy setup.
